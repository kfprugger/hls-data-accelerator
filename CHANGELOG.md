## [Unreleased] — May 28, 2026

### Full component review fixes (2026-11-13–14)

- **Added** `specs/README.md`, the component specification for the deployment script, preflight, every phase, the orchestrator backend and UI, the hosted gateway and sandbox, the add-ons, teardown and the public tickets. Each component states its inputs, behavior contract, verification commands, known limits and status.
- **Added** portable hosted deployment. `hosted/Deploy-HostedOrchestrator.ps1` takes `-DeploymentProfile` (a profile name under `hosted/profiles/` or a path to a `.psd1` file; operators keep their own profile outside Git and copy `hosted/profiles/example.psd1` as the template), `-GitHubRepo` and `-DnsZone`. The registry, vault and storage names are parameters; when they are not set, the script derives deterministic names. The script checks that the signed-in `gh` user is an admin of `-GitHubRepo` instead of checking for one fixed account.
- **Added** `-AllowedDomains` to the hosted deployment script. At deploy time, the script resolves each domain to its Entra tenant through OpenID discovery and adds that tenant to `HLS_ALLOWED_TENANTS`. Approving a domain admits every account in its tenant. Consumer Microsoft-account tenants are refused.
- **Changed** the hosted allowlist defaults. A fork gets no default allowlist, and a fresh deployment with an empty allowlist stops. On a redeploy, the live gateway allowlist stays authoritative: the script keeps the live users and tenants unless you pass `-AllowedUsers`, `-AllowedTenants` or `-AllowedDomains`. A redeploy also reuses the live registry, vault, storage account and custom domain. `hosted/README.md` documents the access policy of `hls.jbatl.dev`: Microsoft employees in the Microsoft tenant plus three operator accounts.
- **Changed** the gateway to take the sandbox registry from `HLS_SANDBOX_IMAGE` instead of a fixed registry name.
- **Fixed** native macOS backend SQL startup when Homebrew's unversioned OpenSSL moves to an unsupported major. `Start-WebUI.ps1` passes the compatible `openssl@3` library directory to the Python child after `nohup`, preserves an explicit caller override and quotes launch arguments. It does not change the caller's `DYLD_LIBRARY_PATH`, global library links or SQL encryption/certificate settings. The root README documents the separate ODBC prerequisite and direct Python startup command.
- **Changed** the WardFlow bundle. It packages `caldova-cardio` and `rayfin-wardflow-persona-app`, and the build stops when either directory is missing at the target commit. `-WardflowCommit none` builds an empty bundle for forks without WardFlow. The sandbox UI build stage uses `node:22-bookworm-slim`, as the Rayfin app engines require.
- **Fixed** repeat alert emails for a device that keeps alerting. `scripts/deploy_clinical_activator.py` builds a stateful Reflex rule: the KQL source returns one row per device with `alert_active`, and the rule fires when `alert_active` becomes greater than 0. A device sends one email per alert episode; it can send another only after it has had no qualifying alert for the cooldown window. `Deploy-All.ps1` passes `-AlertCooldownMinutes` (default 10) as `--cooldown-minutes`. Before, the parameter defaulted to 15 and was never passed.
- **Fixed** `-AlertTierThreshold` having no effect. `Deploy-All.ps1` passes it as `--min-tier` (`WARNING`, `URGENT` or `CRITICAL`; default `URGENT`). Before, the Reflex source always used CRITICAL and URGENT.
- **Fixed** phase switches. `-Phase3` and `-Phase5` no longer deploy the bedside activator, and `-Phase3` skips Phase 7. The bedside activator runs on full runs and on `-Phase4`.
- **Fixed** `-RunEval` checking the wrong device count. `Deploy-All.ps1` passes the expected device associations (115 with the TCGA cohort, else 100), the resource group and the subscription to the evaluation harness.
- **Fixed** the evaluation's Eventstream gate stopping on a transient state after a capacity resume. A Failed node is terminal only when no node is creating, updating, pausing or resuming, the stream is not waiting for this run's resume, and 180 s have passed since the resume. Failures on streams that the run did not touch still stop the gate at once.
- **Fixed** the evaluation telemetry gate rejecting Fabric's HTTP 409 `ArtifactOperationConflict` while an earlier Eventstream operation was still in progress. A refused resume or reset pause now waits for the next topology read within the existing deadline. Accepted lifecycle calls are not repeated. Other errors still fail, and both destination tables must contain current events.
- **Fixed** patient fan-out in the Population Health & Quality model. Its patient relationships pointed to `agg_quality_measures.patient_id`, which is not unique. The six patient relationships now point to `dim_patient`, the distinct patient IDs of seven patient-level tables. Only absent optional sources are skipped and named. Missing required sources, schema drift and read/count failures stop the run before the dimension is written. Summary validation no longer replaces an unreadable table with an empty one; it initializes only genuinely absent optional tables with non-overwriting writes.
- **Fixed** Gold tables left empty after an earlier run created a placeholder. `phase-5/materialize_claims_quality.py` writes every recomputed Gold table with `overwriteSchema`, so real rows replace an empty placeholder (before, `agg_medication_adherence` and 12 other tables could stay empty when the produced schema differed from the placeholder schema). A Gold step whose sources are present but whose read, transform or write fails now fails the run and names the step and table instead of logging a warning. Only a missing source for a step whose outputs are all optional is skipped, and the step and tables are named. Summary validation errors now say whether a read, count, required-table check or placeholder create failed.
- **Fixed** duplicate `dim_hcc` keys. The table has one row per `hcc_code` (19 codes), and `run_pipeline` uses the one module-level CMS-HCC mapping list.
- **Fixed** empty `AppointmentDim.LocationKey` values in POA. Synthetic appointments carry a Location participant, and the demo bundle includes the Location resources.
- **Fixed** FHIR loader failures on throttling. All loader calls share one HTTP session that retries HTTP 429, 5xx and connection errors with backoff, and each response's status is still checked.
- **Fixed** teardown leaving companion items behind. Teardown deletes the UserDataFunction and SQL database items of every known Rayfin app, also when the app backend is already gone.
- **Fixed** preflight results lost when the script printed extra output. The backend parses the last complete JSON document in the preflight output and logs a parse failure with an excerpt.
- **Fixed** hosted deployment parsing of Azure CLI output. JSON parsing uses stdout only. Successful-command stderr is shown as a warning; failed commands retain stderr in the error instead of hiding the Azure failure behind a JSON parse error.
- **Fixed** cancellation on Linux and macOS. Each PowerShell run starts in its own process group, and cancel or shutdown stops the whole group. The kill refuses the server's own process group and runs only when the process leads its group. A finished or failed run always leaves the active-process table.
- **Fixed** concurrent runs on one estate. The backend refuses a deployment, a teardown (single or batch) or an add-on run with HTTP 409 `Another deployment or teardown is active for this estate` while another local run is active on the same Fabric workspace name or the same resource group name. A run is active while its record is Running or Pending, while add-ons it started still run under its Completed deployment (a paused Databricks add-on included), or while its teardown worker is still deleting. A conflicting deployment is refused before its slow preflight checks run. Names compare case-insensitively, and empty names never match. Passive imported peer-sandbox history without a live local worker and teardown-batch parent records do not block. A teardown batch is refused as a whole, before any job starts, when a job collides with an active run or two jobs share a workspace or resource group name. Runs for different estates still run at the same time. Before, only add-on runs had this check, and it matched empty names. The teardown page now shows the refusal instead of starting a mock teardown monitor.
- **Fixed** teardown cancel and reconciliation reporting a state that freed the estate while deletion went on. Teardown deletion cannot be interrupted, so cancelling a teardown whose worker is still running, or whose resource group Azure still reports as deleting, now returns HTTP 409 and leaves the run Running; before, the run was marked Terminated while the worker kept deleting, and a new deployment on the same estate was accepted. Reconciliation skips teardowns that still have a worker. A reconciled Running teardown with no worker becomes Failed when its resource group is gone but other phases did not finish, when Azure no longer reports the group as deleting, or when it has no resource group, so the advised `run the teardown again` is accepted; it used to stay Running, which the estate check above would refuse.
- **Fixed** history deletion bypassing the estate guard. Single-record deletion returns HTTP 409 while local work is active, and bulk clear retains active records. Starting local add-ons on imported history adopts the record before awaited preflight, so its Pending reservation and live worker also prevent conflicting runs and history removal. Failed preflight restores passive peer history when no local add-on task exists. Peer re-import cannot replace a record whose local worker is still active. Inactive history remains removable.
- **Fixed** teardown controls overflowing a 360 px viewport and squeezing workspace names to one character per line. Scan controls and candidate rows now wrap, while row actions remain available. Single and batch HTTP 409 refusals retain the selected teardown page and show the server error instead of opening a monitor.
- **Added** learned stage ETAs. The backend records the duration of each succeeded phase and add-on (the last 20 per stage) in `stage_eta_samples.json` in its data directory. A hosted sandbox also reads the other sandboxes' samples read-only from `HLS_SHARED_DATA_DIR` and skips peer files over 512 KiB. `GET /api/stage-etas` returns the median and the sample count of every stage. The deploy wizard and the phase monitor use a learned median only for a stage with at least 3 samples, and built-in estimates for the other stages.
- **Changed** the device sign-in link to a button. It copies the user code and opens the Microsoft device page in a new tab.
- **Fixed** add-on handling of a missing WardFlow checkout. All add-ons use one `WARDFLOW_ROOT` resolver. When WardFlow is missing, the rayfin add-on skips only the WardFlow persona app and deploys the three repository apps. Alert-recipient warnings show in the add-on status and clear at the start of each run.
- **Added** `npm test` to `orchestrator-ui` (Vitest 3.2.7).
- **Fixed** `rayfin-imaging` lint. The app has an ESLint 9 flat configuration, and the keyboard-handler and effect findings are fixed.
- **Fixed** the Databricks add-on alert hiding a higher tier. Cooldown applies per device and per alert tier in each 15-minute window, so a WARNING no longer suppresses a later URGENT or CRITICAL alert for the same device in that window.
- **Added** CI checks. The repository-data workflow parses the deployment scripts and runs the backend suite. The `databricks-bundle` workflow runs the Databricks implementation tests with hash-locked dependencies.
- **Fixed** Azure credential seal handling. Only the current per-sandbox key and the `HLS2` payload-v2 format are accepted; no legacy-key fallback remains. Startup removes readable legacy seals from the shared mount. Restore and cleanup preserve seals after read errors or incomplete header reads, so a temporary access failure does not delete a valid cache. Sealing and restore accept only a complete sign-in (a profile `subscriptions` list of objects, possibly empty, and a non-empty `RefreshToken` section where every entry has a non-empty `secret`), so an incomplete sign-in never replaces a valid seal or the active CLI cache. Sign-out invalidates in-flight seals: the CLI files are read under the seal lock, sign-out removes the CLI files before the seal, and a seal write that lands during sign-out is deleted. When a seal write is still in flight after sign-out's wait for it, `POST /api/auth/logout` no longer reports `signed_out`: it returns HTTP 503 with `Retry-After: 10` and asks the user to sign out again, which succeeds once that write has landed and removed itself. The lock file beside the seal is broken and released only through an exclusive-create election, so two waiters never take the same lock at once; a holder stalled for more than 60 s can still lose the lock while it runs. SMB delete-pending (`ENOENT`) is retried within the timeout, and a failed token write leaves no orphan lock. Sign-in and sign-out wait off the event loop. Each wait is bounded at 10 s, but sealing and sign-out can each make two waits in sequence (the seal lock, then the write guard); a write-guard timeout is not retried as a lock failure. The first release from this branch requires one Azure sign-in for users with older seals.
- **Fixed** alert stopwatch results that reported a prediction as a delivery. `scripts/trigger_spo2_alert.py` now predicts `EXPECTED_DISPATCH`, `SUPPRESSED_DEDUPE` or `UNCERTAIN_BOUNDARY` from Eventhouse history (`email_expected`), and reports `DISPATCHED` only when the alert email is seen (`DISPATCH_NOT_OBSERVED` when it is not). Each drop carries `metadata.alert_probe_id`; T1 is the ingestion time of that row, T2 needs an alert row joined to it, and T3 needs an email whose subject carries `[probe <id>]`, which the Reflex now renders. Missing, offset-less, malformed or pre-drop timestamps stay `not_observed`. Dry runs make no network calls and report planned beats with no timings (the invented 2.3/8.1/18.4 s values are gone). The history query uses the deployed SpO2 and pulse-rate predicates and covers the cooldown, Reflex poll interval and latency allowance; malformed or incomplete Kusto results stay uncertain. Invalid settling times fail before authentication or network access. Importing alert modules no longer changes process-wide networking. The rayfin add-on passes `--cooldown-minutes` to both alert scripts and fails when the live trigger fails, instead of recording a warning.
- **Fixed** three alert stopwatch faults. The history query now escalates a reading's tier the same way the enriched `fn_ClinicalAlerts` does: WARNING becomes URGENT and URGENT becomes CRITICAL when a patient linked to the device has a high-risk condition. A high-risk patient's recent alert inside the cooldown now predicts `SUPPRESSED_DEDUPE`, not `EXPECTED_DISPATCH`. If the trigger cannot get the high-risk flag, it predicts `UNCERTAIN_BOUNDARY`. The result field `poll_errors` keeps the last Eventhouse error of the baseline, T1 and T2 polls, and the live failure message shows the T1 and T2 errors. The rayfin add-on no longer reads the unused `alert_cooldown_minutes` and `alert_cooldown` settings. It passes one 10-minute cooldown constant to both the Reflex deploy and the trigger.
- **Fixed** shared run-history import accepting a partial, contradictory or malformed target match. `import_target_history_from_shared_storage` needs both the signed-in tenant and subscription, and checks each peer deployment or teardown record on its own. A record is imported only when one of its target sources (`customStatus.expectedTenantId`/`subscriptionId`, `customStatus.deployConfig`, or the root `config` column) holds the same tenant and the same subscription, and every other non-empty tenant or subscription field in the record agrees. `customStatus` must be a mapping; `deployConfig` is absent only when its key is missing and the root `config` only when the column is SQL NULL, so a stored JSON `null`, `[]`, `""`, `0`, `false` or unreadable text rejects the record even when another source holds a matching pair. An empty mapping is valid but holds no pair. ID fields must be missing, `null` or strings. Records with an absent, different or conflicting tenant or subscription, records whose tenant and subscription appear only in different sources, and records rebuilt from a ledger (whose IDs were inferred from a sign-in) are never imported. Form history now comes only from the imported records, and no peer state-tracking ledger is copied or rebuilt, because ledgers record no target. Before, import ran with only one target ID, a record without a tenant matched on subscription alone, a target `deployConfig` hid a foreign `customStatus` target, malformed or falsey sources were read as absent, a record with neither ID was imported from any qualifying peer, and a qualifying peer's whole form history and every ledger came with it. The import result now holds `importedDeployments` and `importedFormHistory`; `reconstructedLedgers` is removed. History already imported is not deleted.
- **Fixed** `specs/README.md`: Component 6 lists only Patient 360 and Clinical Triage for `phase-2/deploy-data-agents.ps1`, and Component 8 documents the Healthcare Graph Agent that `phase-7/deploy-payer-rti.ps1` deploys and `-SkipGraphAgent` skips. Component 3 states the `-PatientCount` default per entry point: 100 in `Deploy-All.ps1`, 10 for a standalone `phase-1/deploy-fhir.ps1`. Runtime defaults are unchanged.
- **Fixed** telemetry readiness after a Fabric capacity restart. The evaluator re-reads topology after `ArtifactOperationConflict` instead of treating a deferred pause or resume as accepted. Failed destination nodes can settle while the stream changes state and for 180 seconds after an accepted resume. Stable failures and deadline exhaustion still fail the check. Running nodes alone do not pass it; both destination tables must contain current events.
- **Fixed** Rayfin post-provision deployment reapplying the data model after installing the command center's SQL publication guard. Static content and enabled functions now use the native service-specific publish commands. The configured static build keeps its Power BI token and working directory, preserves shell operators and quoting, and propagates pipeline failures with Bash `pipefail`. Required origin registration uses the installed CLI's settings helper and a read-back check, including the cardiology companion, without another schema application. Existing databases can still refuse the initial full provision when their custom guard differs from the managed schema; asset-only publishing does not remove that guard or migrate changed entities.

### Hosted sandbox hardening and add-on runtime (2026-11-07 to 2026-11-10)

- **Changed** the hosted Azure sign-in seal. The AES key now comes from the per-sandbox gateway key, with the user's `tid:oid` bound in as HKDF info. The old key came from `tid:oid` alone, so any sandbox on the shared Azure Files root could decrypt another user's refresh token. The sandbox does not read a seal written under the old key: after this update, each user signs in to Azure once, and that sign-in replaces the old seal.
- **Added** hotfix validation for hosted sandboxes. A hotfix tar in the sandbox's own `HLS_DATA_DIR` applies only when its `.hls-hotfix-commit` member equals the image's `HLS_IMAGE_COMMIT`. Any other tar is renamed `<name>.rejected` and is not unpacked. Tars in the shared root are refused. A failed unpack stops the sandbox at start. Applied tars apply again at boot while their marker matches the image.
- **Changed** the sandbox image build. `Deploy-HostedOrchestrator.ps1` archives one resolved commit and passes it as the `HLS_IMAGE_COMMIT` build argument. The Dockerfile rejects a value that is not a 40-character SHA.
- **Changed** shared run-history import. Peer snapshots open read-only (`mode=ro`), and nothing is written into a peer directory. Imported runs carry `customStatus.importedFrom`; they do not count as active runs, and restart recovery skips them. An import replaces only unknown IDs and earlier imports, never a run that this sandbox owns.
- **Fixed** continuation phase skips. The skip decision uses the latest outcome of each phase across the continuation chain, so an older failure no longer blocks a phase that a newer attempt completed.
- **Changed** Databricks metastore-pause continuations to live in `orchestrator/shared/continuations.py`, so a hot reload of `activities.addons` keeps them.
- **Fixed** the sandbox image for add-ons. The orchestrator venv installs `utilities/repository-data-requirements.lock`, so the rayfin add-on finds `pyarrow`. The image ships the repo-root `scripts/` directory, so the researcher persona, clinical activator and SpO2 stopwatch steps can run.
- **Fixed** the Databricks OneLake interop step failing with "Expected exactly one clinical_lakehouse, found 0". The step lists Fabric items again before the lookup, because the rayfin add-on creates the lakehouses later in the same run. When the Rayfin lakehouses are absent, the step is marked skipped with the reason.
- **Fixed** the rayfin add-on's Silver TCGA check. It imported a function that does not exist and queried columns that HDS Silver does not have. It now reads `identifier_string` for the GDC TCGA barcode over pyodbc and ODBC Driver 18. `04-unity-catalog-bootstrap.sh` treats `DELTA_FEATURE_DROP_FEATURE_NOT_PRESENT` as an already-dropped `catalogManaged` feature, so reruns succeed.
- **Fixed** recovered PowerShell retries counted as errors. The log classifier uses the explicit `[INFO]`, `[WARN]` and `[ERROR]` tags before keyword matches, so a recovered retry no longer forces an HDS pipeline rerun.
- **Changed** the demonstration add-on steps (ticket 012). The rayfin add-on runs TCGA cohort seeding (default on), the researcher persona (opt-in `enable_researcher_persona`), the SpO2 alert stopwatch and clinical activator (default on; needs an alert email) and Databricks interop (default on). A failed step raises with the script's error output, and a missing script raises. `Deploy-All.ps1` calls `scripts/deploy_clinical_activator.py` instead of its inline Reflex builder.
- **Added** elapsed timers to the deployment history and a final duration to the phase monitor ("Completed in", "Failed (…)", "Cancelled (…)"). A finished run uses `completedAt` or the backend `durationSeconds` before the sum of phase durations.
- **Added** a "100% synthetic / public de-identified data" badge with a HIPAA Safe Harbor note to the rayfin-imaging header.

### Az PowerShell tokens, HDS run reuse and Reflex retries (2026-11-09)
